# Protocol-RED 맵 제작 도구

위에서 내려다보는 2D 픽셀 게임의 맵을 만들고, 맵 수십 개를 순서대로 관리하는 도구예요. 설치할 게 없어요.

## 열기

`index.html` 파일을 **더블클릭**하면 브라우저에서 열려요.

- **Chrome이나 Edge로 열어 주세요.** 다른 브라우저에서는 맵 목록과 편집 화면이 서로 맵을 못 볼 수 있어요.
- 항상 **같은 브라우저, 같은 파일 위치**에서 열어야 만든 맵이 보여요.

## 맵 만들기

1. 맵 목록에서 **＋ 새 맵**을 누르고 이름과 크기(가로 × 세로 칸 수)를 정해요. 기본은 40×30칸이고, 가장 크게는 **1000×1000칸**까지 정할 수 있어요.
   - 1000×1000처럼 아주 큰 맵을 블록으로 가득 채우면 컴퓨터 메모리를 많이 써서(수백 MB) 느려질 수 있어요. 처음에는 작게 만들고 필요할 때 **크기 변경**으로 키우는 걸 추천해요.
2. 만든 맵의 **열기**를 누르면 편집 화면이 열려요.
3. 왼쪽에서 **층**(바닥 / 바닥꾸미기 / 벽 / 벽꾸미기 / 물건 / 시작점)과 종류 탭을 고르고, 블록을 눌러 고른 다음 맵을 클릭해요. 누른 채 끌면 쭉 이어서 놓여요.
   - 층은 아래부터 **바닥 → 바닥꾸미기 → 벽 → 벽꾸미기 → 물건** 순서로 겹쳐 보여요. 바닥 위에 바닥꾸미기(얼룩·무늬 등), 벽 위에 벽꾸미기(포스터·조명 등), 맨 앞에 물건(캡슐·상자 등)이 와요.
   - **같은 층** 안에서는 블록끼리 겹치지 않아요. 새 블록을 놓으면 겹친 블록은 통째로 바뀌어요. 하지만 **다른 층끼리는 겹쳐 놓을 수 있어요**(벽 앞에 물건을 놓아도 벽은 그대로예요).
   - 여러 칸짜리 건물은 가장자리에 걸치면 놓이지 않아요.

| 도구 | 하는 일 |
|---|---|
| 붓 | 블록을 하나씩, 또는 끌어서 이어서 놓기 |
| 사각형 | 끌어서 영역을 한 번에 채우기 |
| 지우개 | 눈에 보이는 **맨 위 블록부터** 지우기(시작 깃발 → 물건 → 벽꾸미기 → 벽 → 바닥꾸미기 → 바닥). 어느 층이 선택돼 있든 상관없이 같은 칸을 계속 누르면 아래 블록도 차례로 지워져요 |

- **되돌리기 / 다시하기**: 위쪽 버튼 또는 `Ctrl+Z`, `Ctrl+Y`(맥은 `Cmd`). 끌어서 놓은 건 한 번에 되돌려져요.
- **확대·축소**: 마우스 휠, 또는 아래 `−` `＋` 버튼. **전체 보기**를 누르면 맵 전체가 한눈에 보여요.
- **화면 이동**: 마우스 **오른쪽 버튼**을 누른 채 끌기(블록은 놓이지 않아요). 스페이스바를 누른 채 끌기, 마우스 가운데 버튼으로 끌기도 돼요.
- **격자**: 칸 선을 켜고 끌 수 있어요.
- **크기 변경**: 위쪽 버튼. 줄이면 밖으로 나가는 블록이 사라지는데, 몇 개인지 알려주고 확인해요. 크기를 바꾸면 되돌리기 기록이 지워져요.

## 꼭 해 두세요: 백업

맵은 이 브라우저 안에 **자동으로 저장**돼요. 그런데 브라우저 기록을 지우면 맵도 같이 사라질 수 있어요.

- 맵 목록 위쪽의 **전체 내보내기**를 눌러 파일(`protocol-red-maps-날짜.json`)을 받아 두세요. 가끔, 그리고 큰 작업 뒤에 꼭요.
- 받은 파일을 Claude에게 주면 프로젝트 폴더(`data/maps/`)에 정식으로 보관해 줘요.
- **불러오기**로 그 파일을 다시 올리면 맵이 **추가**돼요(기존 맵은 지워지지 않아요).
- 저장 공간이 가득 차면 화면에 노란 경고가 떠요. 그때는 바로 내보내기를 해 주세요.

## 블록 그림 만들기 (챗지피티에게 요청할 때)

> 2D 탑다운 픽셀 게임용 그림입니다. 투명 배경 PNG 파일로, 한 칸이 정사각형이 되는 비율로 만들어 주세요(예: 가로 1칸 × 세로 2칸이면 가로:세로가 정확히 1:2). 그림 주변에 여백이나 테두리, 글자 없이 그림이 칸에 꽉 차게 해주세요. 해상도는 높을수록 좋아요.

- 그림은 **원본 크기 그대로** 주세요. 크기를 줄이면 흐려지고 깨져요. 정해진 크기는 없고, **칸 수와 같은 비율**이면 돼요(한 칸은 정사각형, 가로 3칸·세로 2칸이면 3:2). 한 칸이 64픽셀보다 작으면 흐려질 수 있어요.
- 화면에서는 그림을 칸 크기에 맞춰 부드럽게 줄여서 보여줘요(확대해도 원본 그대로 선명해요).
- 한 장에 여러 블록을 격자로 모아서 줘도 돼요. Claude가 칸 크기대로 잘라서 등록해요.
- 블록마다 **이름**과 **걸어갈 수 있는지/막히는지**를 알려 주세요.
- 블록이 하나도 없는 층은 "아직 블록이 없어요"라고 안내가 보여요.

### 애니메이션 블록(움직이는 블록)

- 프레임을 **격자 한 장**(예: 4×4 = 16프레임)으로 모아서 주세요. 프레임은 위쪽 줄 왼쪽부터 오른쪽으로 순서대로 재생돼요.
- 프레임 한 장이 차지하는 칸 수와 **초당 프레임 수**(속도)를 알려주세요. 말씀이 없으면 초당 12프레임이에요.
- 등록할 때 도구가 격자에 딱 나누어떨어지는지, 프레임 사이에 같은 그림이 이어지지 않는지, 마지막에서 처음으로 돌아올 때 튀지 않는지, 프레임 경계가 분명한지를 검사해서 알려줘요.
- 에디터에서는 움직이는 블록이 화면에 있을 때만 계속 다시 그려요. 아주 작게 줄여 보면(칸이 6픽셀 미만) 첫 프레임 색으로만 보여요.

### 개발자용: 블록 등록 방법

`data/blocks.js`가 블록 정식 목록이고, 그림 파일은 `assets/blocks/`에 있어요. 그림 검사와 자르기는 도구로 해요(처음 한 번 `npm install`).

```bash
node tools/slice-sheet.js sheet.png --prefix wall --names "벽,벽 모서리" --layer objects --category 벽 --out assets/blocks
```

그림 한 장은 `--whole --size 가로x세로`(예: `--size 1x2`)를 붙이면 자르지 않고 **원본 크기 그대로** 등록해요. 비율이 칸 수와 안 맞으면 경고를 보여줘요. 출력된 줄을 `data/blocks.js`에 붙여 넣으면 돼요. (격자 한 장을 칸으로 자르는 방식은 한 칸이 정확히 64픽셀이어야 해요.) 애니메이션 시트는 `--whole --anim 4x4 --fps 16 --size 1x1`처럼 프레임 격자와 속도를 함께 주면 한 항목(`anim: { frames, cols, rows, fps }`)으로 등록해요.

## 맵 파일 형식 (개발자용)

맵은 맵마다 JSON이에요. 나중에 게임 프로그램(Godot 등)에서도 읽기 쉬운 일반 형식이에요.

| 필드 | 뜻 |
|---|---|
| `version` | 파일 형식 버전 (지금은 1) |
| `id`, `name` | 맵 번호표와 이름 |
| `width`, `height`, `tileSize` | 가로·세로 칸 수, 한 칸 크기(64) |
| `floor`, `floordeco`, `walls`, `walldeco`, `objects` | 층별 블록 목록(아래부터 바닥·바닥꾸미기·벽·벽꾸미기·물건). 항목은 `[블록id, x, y, n]` — (x, y)부터 가로로 `n`개(블록 너비 간격). `floordeco`·`walls`·`walldeco`는 나중에 생겨서 예전 파일에는 없을 수 있어요 |
| `start` | 시작점 `{x, y}`(칸 좌표) 또는 `null`. 에디터의 **시작점** 층에서 빨간 깃발로 놓아요. 맵에 하나뿐이고, 게임에서는 이 칸에서 시작해요(깃발 그림은 에디터에서만 보여요) |
| `exits` | 지금은 쓰지 않아요(빈 목록) |

여러 칸 블록의 `x, y`는 왼쪽 위 칸이에요. 블록의 크기와 통과 가능 여부는 `data/blocks.js`에 있어요.
