# 맵 제작 도구 설계 (Protocol-RED)

작성일: 2026-11-25 / 상태: 사용자 승인 대기

## 1. 무엇을, 왜 만드나

스팀 출시를 목표로 하는 위에서 내려다보는 2D 픽셀 게임(아이작·좀비고 같은 평면형)의 **맵을 만들고 관리하는 도구**를 만든다.

- 사용자는 코딩을 하지 않고 Claude로 만든다(바이브코딩). 그래서 도구도 말로 쉽게 설명할 수 있고, 마우스만으로 쓸 수 있어야 한다.
- 블록(타일·구조물) 그림은 챗지피티가 만든 그림 파일이다. 사용자가 블록을 한 개씩 설명과 함께 주면, 도구의 블록 목록에 등록한다.
- 사용자가 직접 마우스로 블록을 골라 맵 위에 배치한다.
- 맵은 수십 개가 될 것이고, 게임에서는 맵을 클리어하면 다음 맵으로 넘어간다. 그래서 맵을 순서대로 모아 보는 목록 페이지가 필요하다.

## 2. 목표 / 하지 않을 것 / 실패로 보는 것

**목표**
- 검은 배경 위에 블록을 배치해서 맵을 만든다.
- 확대·축소와 전체 보기가 되어서 아주 큰 맵도 다룰 수 있다.
- 맵 목록 페이지에서 맵 수십 개를 순서대로 보고 관리한다.
- 맵 데이터가 나중에 게임 프로그램(예: Godot)으로 옮겨도 버려지지 않는 일반적인 파일 형태다.

**이번에 하지 않을 것**
- 캐릭터가 실제로 걸어 다니는 게임 화면(다음 단계).
- 게임 프로그램용 내보내기 기능(게임 프로그램을 정한 뒤에 한다).
- 몬스터·아이템 배치 등 게임 규칙 요소. 단, 시작 지점과 출구 표시는 넣는다(8장).
- 사용자가 화면에서 직접 그림 파일을 올리는 기능. 블록 등록은 Claude가 한다(7장).

**실패로 보는 것**
- 맵이 브라우저 저장소에만 있다가 사라져서 작업이 날아가는 것.
- 블록 그림이 흐려지거나 칸에 안 맞는 것(픽셀 그림은 선명해야 한다).
- 맵이 커졌을 때 느려서 쓰기 힘든 것.

## 3. 접근 방식 (검토한 것들)

| 방식 | 장단점 | 결과 |
|---|---|---|
| A. 브라우저에서 열리는 전용 맵 도구를 처음부터 만든다 | 설치가 없고, 블록 등록·맵 목록·저장 방식을 원하는 대로 맞출 수 있다. 기능을 직접 만들어야 한다. | **선택(사용자 승인)** |
| B. 게임 프로그램(Godot 등)에 맵 기능을 얹는다 | 나중에 게임에는 좋지만 지금은 설치와 사용법 배우기가 먼저 필요하다. | 제외 |
| C. 기존 무료 맵 프로그램(Tiled)을 쓴다 | 만들 게 거의 없다. 하지만 맵 목록·다음 맵 구성은 따로 만들어야 하고 설치가 필요하다. | 제외 |

이 도구는 개발자(사용자)만 쓰는 제작 도구라서 스팀에 판매되는 게임에는 들어가지 않는다. 실제 게임은 나중에 게임 프로그램(Godot 등)으로 만들고, 이 도구가 만든 맵 파일을 읽는다.

## 4. 사용자가 정한 것 / 내가 정한 것

**사용자가 정함**
- 방식 A.
- 블록은 챗지피티가 만든 그림 파일이고, 사용자가 한 개씩 설명하며 준다.
- 한 칸 크기 64×64 픽셀.
- 배치는 사용자가 직접 한다.
- 이번에는 맵 만들기 페이지와 맵 목록 페이지까지만 만든다.

**내 판단(사용자가 바꿀 수 있음)** — 아래 표시 `[내 판단]`

## 5. 화면 구성

### 5-1. 맵 목록 페이지 (`index.html`)
- 맵 카드가 번호 순서대로 늘어선다. 카드에는 맵의 작은 미리보기, 번호, 이름, 크기(예: 40×30칸)가 보인다.
- 카드를 누르면 그 맵의 편집 화면으로 간다.
- 맵 추가(이름·크기 입력), 복제, 삭제(확인 창 필수), 순서 바꾸기(끌어서 옮기기)가 된다.
- 위쪽에 "전체 내보내기"와 "불러오기" 버튼이 있다(9장).

### 5-2. 맵 편집 페이지 (`editor.html`)
```
┌────────────────────────────────────────────────────┐
│ ← 맵 목록   맵 3: 지하 창고    [되돌리기][다시][저장됨] │
├───────────┬────────────────────────────────────────┤
│ 도구      │                                        │
│ 붓 사각형 │          (검은 배경의 맵 판)            │
│ 지우개    │                                        │
│ 층: 바닥  │                                        │
│     물건  │                                        │
│ ───────── │                                        │
│ 블록 목록 │                                        │
│ [벽][벽2] │                                        │
│ [바닥]... │                                        │
│           │ [−] 100% [+]  [전체 보기]  [격자 on/off]│
└───────────┴────────────────────────────────────────┘
```
- **블록 선택**: 왼쪽 목록에서 고르면 마우스에 블록이 따라붙는다. 클릭하면 놓이고, 누른 채로 끌면 연달아 놓인다.
- **도구**: 붓, 사각형 채우기(끌어서 영역을 채움), 지우개. 되돌리기·다시하기(최소 50단계).
- **확대·축소**: 마우스 휠, + − 버튼. 마우스가 있는 곳을 기준으로 확대된다. 4%~400%.
- **전체 보기**: 맵 전체가 화면에 딱 맞게 들어온다.
- **이동**: 스페이스바를 누른 채 끌기, 또는 마우스 가운데 버튼 끌기.
- **격자**: 칸 선을 켜고 끌 수 있다. 맵 가장자리는 항상 테두리로 보인다.
- 한 칸에 놓인 것을 구분하기 쉽도록 블록 목록은 종류별(바닥, 벽, 물건…) 탭으로 나뉜다.

## 6. 칸과 층 `[내 판단]`

- 한 칸은 64×64. 맵 크기는 가로·세로 칸 수로 정하고, 처음 만들 때 지정한다(기본 40×30, 최대 200×200). 맵을 만든 뒤에도 크기를 바꿀 수 있다(줄일 때는 잘려나가는 부분이 있으면 경고).
- **층은 두 개**: ① 바닥(타일), ② 물건(벽·구조물·장식 등 바닥 위에 올라가는 것). 바닥 위에 벽을 놓는 흔한 경우를 한 칸에 겹쳐 둘 수 있게 하기 위해서다.
- 구조물이 여러 칸을 차지하면(예: 192×128 = 3×2칸) 한 번 놓을 때 그 칸들을 모두 차지한다. 놓으려는 자리에 이미 다른 물건이 있으면 기존 것을 대체하되, 큰 구조물의 일부만 지워지는 일이 없도록 구조물 전체를 지운다.

## 7. 블록 등록 방식

- 블록의 진짜 목록은 프로젝트 안의 파일(`data/blocks.js`(file://로 열어도 읽히도록 JSON이 아닌 스크립트 파일))과 그림 파일 폴더(`assets/blocks/`)다.
- 사용자가 그림과 설명을 주면 Claude가 등록한다. 한 장에 여러 블록이 격자로 모여 있으면, 64×64 단위로 잘라서 각각 등록한다(자르는 작업은 Claude가 한다). 크기가 64의 배수가 아니거나 배경이 투명하지 않으면 사용자에게 알린다.
- 블록 한 개의 정보: 이름, 그림 파일, 차지하는 칸 수(가로×세로), 종류 탭(바닥/물건), **통과 가능 여부**(걸어갈 수 있는지, 막히는지) `[내 판단]` — 게임에서 필요한 정보라서 처음부터 같이 적어 둔다. 사용자가 설명할 때 알려주지 않으면 물건은 "막힘", 바닥은 "통과"를 기본으로 하고 표시해 둔다.
- 사용자가 블록 그림을 주기 전에도 도구를 시험할 수 있도록 색깔 칸 몇 개를 임시 블록으로 넣어 둔다. 실제 그림이 등록되면 교체한다.
- 그림은 확대해도 번지지 않도록(픽셀이 선명하게) 보여준다.

## 8. 시작 지점과 출구 `[내 판단]`

"클리어하면 다음 맵"이 게임의 핵심이라서, 맵마다 **시작 지점 1개**와 **출구 1개 이상**을 표시할 수 있는 특별한 블록을 둔다(눈에 띄는 색깔 표시). 맵 목록의 카드에는 시작·출구가 빠진 맵에 "미완성" 표시를 붙인다. 게임 규칙(출구가 언제 열리는지 등)은 나중에 게임 단계에서 정한다.

## 9. 저장 — 가장 조심할 부분 `[내 판단]`

- 편집하는 동안은 브라우저에 **자동 저장**한다(저장됨/저장 중 표시).
- 하지만 브라우저 저장소는 기록 삭제로 사라질 수 있다. 그래서 목록 페이지에 **"전체 내보내기"**(맵 전부를 파일 한 개로 받기)와 **"불러오기"**를 두고, 내보낸 파일을 주기적으로 받아 두라고 안내한다. 내보낸 파일을 Claude에게 주면 프로젝트 안(`data/maps/`)에 정식으로 보관해 준다.
- 맵 파일은 맵마다 일반적인 텍스트 형식(JSON)이다. 들어가는 내용: 파일 형식 버전, 맵 이름, 가로·세로 칸 수, 한 칸 크기(64), 바닥 층과 물건 층(각 칸에 어떤 블록이 있는지, 여러 칸 구조물은 왼쪽 위 칸 기준으로 한 번만 기록), 시작 지점, 출구 목록. 다른 게임 프로그램에서도 읽기 쉽다.
- 맵 순서는 별도 파일(`data/maps/order.json` 또는 내보내기 파일 안)에 기록한다.

## 10. 만드는 방식(기술 선택, 내 판단)

- 설치가 필요 없는 순수한 웹 페이지(HTML/CSS/JavaScript)로 만든다. 특별한 도구나 서버 없이 파일을 열기만 하면 동작하도록 한다.
- 맵 판은 화면에 그리는 방식(캔버스)으로 그려서 큰 맵(200×200)에서도 부드럽게 한다. 화면에 보이는 칸만 그린다.
- 폴더 구성: `index.html`(맵 목록), `editor.html`(편집), `css/`, `js/`, `assets/blocks/`, `data/`.

## 11. 검증 방법

- 브라우저 자동 조작(Playwright)으로: 블록 놓기, 지우기, 되돌리기, 확대·축소·전체 보기, 큰 맵(200×200)에서의 속도, 맵 추가·복제·삭제·순서 변경, 내보내기→불러오기 후 내용이 같은지를 확인한다.
- 화면 사진을 찍어서 사용자에게 보여준다.

## 12. 빌더에게 맡기는 것
- 정확한 색상·글꼴·버튼 배치(검은 배경에 어울리는 어두운 톤).
- 단축키(되돌리기 Ctrl+Z 등).
- 큰 맵 속도를 위한 구체적인 그리기 방법.

## 13. 단계
1. 맵 목록 + 편집 화면 기본(블록 놓기·지우기·확대·전체 보기·자동 저장·내보내기/불러오기), 임시 블록.
2. 사용자가 준 실제 블록 그림 등록.
3. 시작·출구, 미완성 표시, 다듬기.
